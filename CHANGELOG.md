# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **GIF studio, 'AI clip (text-to-video)' mode — a real generative video model animates
  everything INSIDE the scene**. While the GIF modes draw frames and the motion is
  assembled locally (Lottie vectors, procedural warp, AI frames), OpenRouter now also
  exposes its **async video API**: `POST /api/v1/videos` (submit) -> poll the job ->
  download a normal **MP4**. New module `ai_clips.py`: `plan_clip_prompt` (the text model
  turns the scene + movement into ONE vivid cinematic prompt — camera, action, lighting,
  looping-friendly, editable), `generate_video_clip` (submit/poll/download with a progress
  callback for the live log, `ProviderError` on failed/expired jobs and on timeout), and
  the `VIDEO_MODELS` dropdown (Veo 3.1 Lite, Seedance 2.0 Fast, Grok Imagine 1.5 Lite, Wan
  2.7, Hailuo 2.3 — paid per second, so the UI exposes a 4-15 s duration slider). The MP4
  goes STRAIGHT into the video pipeline: the render engine already loops video shots
  (`-stream_loop -1`), so this is the mode where the AI truly animates the objects inside
  the scene (walking animals, moving characters), at the cost of a per-second price.
- **GIF studio, 'Cartoon character' Lottie kind — the AI animates real vector characters**.
  In 'Motion design (Lottie)' mode the user can now pick the animation kind: **'Cartoon
  character'** (default; the model builds the character from shape groups — head, torso,
  arms, legs — animates it with classic cartoon principles: walk cycle with limbs rotating
  from their joints in antiphase, body bob, eye blink, squash-and-stretch, walk-in-place so
  the loop is seamless by construction) or 'Infographic vector' (icons, arrows, lines).
  Because every limb is a separate vector shape with its anchor at the joint, the animation
  moves the objects INSIDE the scene — no image warping, no drift.
- **GIF studio, 'Motion design (Lottie)' mode — the AI writes professional vector
  animations**. Following the user's request for an AI-agnostic GIF animator driven by the
  AI, GIF studio now adopts the **Lottie (Bodymovin) format**, the industry standard for
  professional explainer motion design. The TEXT model writes the whole animation as a
  Lottie JSON (shapes, lines, icons, keyframed motion, trim-path line drawing — no raster
  images at all, so the scene can never drift between frames); `python-lottie` (pure
  Python, no AI inside, added to the `webui` extra) validates the JSON and renders the
  seamless-looping GIF (needs cairosvg + libcairo, installed by Colab cell 1) plus a live
  **HTML preview** playable in the browser. The UI normalizes the timeline (30 fps, exact
  canvas, seamless first==last keyframe guidance in the system prompt), and the new default
  GIF-studio mode is 'Motion design (Lottie)'; 'One image + procedural motion' and 'AI
  frames' remain selectable.
- **GIF studio, 'One image + procedural motion' mode (zero-drift GIFs)**. Text-to-image
  models redraw a slightly different scene at every call, so multi-frame AI animations kept
  'wobbling'. The new default mode asks the image model for the scene only ONCE and applies
  the movement locally with a cyclic, sinusoidal transform (Pillow): `wind` (top-heavy sway
  for ears, grass, flags), `waves` (bottom-heavy sway for water), `breathe` (cyclic zoom),
  `shimmer` (subtle sway), with an adjustable strength and loop duration. The phase wraps
  around 2π exactly, so the loop **cannot** drift: it returns to the exact starting frame
  by construction, with one API call. The previous 'AI frames' mode (N drawn frames,
  ping-pong + cross-fades) stays available for subjects whose movement must be literal
  (crawling worms, walking animals). Research note: specialized frame-interpolation tools
  (RIFE / FILM) interpolate between 2 given frames but add GPU checkpoint dependencies, so
  the interpolation-free procedural route was chosen to stay light on Colab and Chromebook.
- **GIF studio: a workshop tab dedicated to true animated GIFs, to test the motion before
  building the video**. The AI splits the scene into N frame prompts of the SAME scene
  (identical camera, composition and colors — only the phase of the movement changes:
  swaying wheat, crawling worms...), each frame is generated by the image model, and the
  GIF is assembled locally: ping-pong order (forward + backward) so the loop **returns
  exactly to its starting frame with no discontinuity**, an adjustable loop duration and
  optional cross-fade frames that smooth out any small drift between the AI frames.
- **AI Illustrations tab: clips-free videos made only of AI drawings, animated**. The AI writes
  the narration, describes one image prompt per scene (editable, one per line), an OpenRouter
  image model generates the illustrations (20+ artistic style presets, free-text style detail,
  16:9/1:1/9:16, SVG answers rasterized via cairosvg when installed), and each picture is
  locally animated into a **looping Ken Burns GIF** (push-in / pan / pull-out / pan + rise) with
  the text/icon cards **baked in superimposition**, so the shots stay in motion for their whole
  duration. The GIFs are rendered as normal video shots by the unchanged engine, with the
  usual script, quick preview and final render.

### Fixed
- **Colab keeps re-running an old build**: since the package version did not change between
  commits, `pip install pkg @ git+…` answered "already satisfied" and the notebook silently
  ran the previous code. The notebook now force-reinstalls the package from Git on every run
  and prints the installed version right after, and the version was bumped to 0.4.0 with the
  new wizard/tabs to make updates visible at a glance.
- **The video-wizard steps were nested inside the AI Illustrations tab**: when that tab was
  added, the `Video wizard` tab opener was lost in the refactoring, so the wizard's entire
  step list appeared — after the final render — as a continuation of the AI Illustrations
  tab. The tab boundary is restored; the tabs are now fully separate end to end.

### Fixed
- **Step 5 (download, cut and classify) errors are now readable in the UI**: the button runs as a
  streaming generator, which bypassed the friendly-error wrapper, so failures appeared as a bare
  `Error` toast. Every failure now surfaces with its class and detail (for example a missing
  `yt-dlp` or OpenRouter key), and if no clip is produced at all the per-source failures are
  reported directly in the popup instead of vanishing.
- **Colab: step 5 works out of the box**: the notebook now installs the `clip` extra (yt-dlp,
  needed by the default YouTube + Commons sources) and prints an explicit `yt-dlp OK` /
  `ffprobe OK` check at the end of the installation cell.
- **The narration is no longer rewritten at clip selection**: with the guided wizard, the
  step-1 narration is used exactly as written — the model only pairs each paragraph with the
  best catalog clip (paragraphs without a fitting clip render as animated text, so the video
  still lasts the full reading time). The old model-written-narration behavior remains for
  flows without a step-1 script.
- **Visible errors in the web studio**: handler failures now surface their real message in
  the UI (instead of a bare "Error" toast) and the server launches with `show_error=True` so
  the full traceback is available in the error modal; the Colab notebook picks a free port
  so a second launch no longer crashes.
- **Clearer OpenRouter errors and model fallback in the Clip studio**: every OpenRouter HTTP
  error now carries an actionable hint (invalid key → openrouter.ai/keys, 402 → no credits,
  404 → model no longer served, 429 → rate limited), and *Suggest search queries* automatically
  retries on the default model when the chosen one fails instead of aborting.
- **Clip studio disk safety**: sources are downloaded as small (<=720p) video-only files and,
  once the model has picked the highlights, only those sections are fetched (yt-dlp
  `download_ranges`), so a 30-minute source costs a few megabytes instead of gigabytes. The
  source file is deleted after cutting, a failing clip no longer aborts the batch, a full disk
  stops everything with a clear message, and search results skip videos longer than 30 minutes.
  The pause between YouTube requests now defaults to 10 s and also covers subtitle fetches; a
  429 on subtitles is reported instead of silently continuing.
- **AI Video resilience**: a scene whose asset cannot be found no longer aborts the whole plan —
  it continues without a visual and renders as animated text, and the UI reports which scenes have
  no asset. Pollinations generation retries with fresh seeds and reports rate limiting clearly;
  keyless searches try progressively broader keyword sets.
- Edge engine: the `edge-tts` requirement is now `>=7.2.7` (Microsoft changed the read-aloud
  service in December 2025 and older versions fail with "No audio was received"), and the error
  message suggests the upgrade when that exact failure occurs.

### Added
- **AI polish: the model watches the video and improves it, HeyGen-style**. After the quick
  preview, a new step samples frames, scores the render 0–10 for professionalism with the
  vision model and applies what can be fixed automatically — color correction (dark/washed-out
  frames via an ffmpeg eq pass), overlay cards redrawn in a contrasting style when the text is
  hard to read, clips swapped for better-matching unused catalog entries when a shot does not
  fit the narration — then re-renders and reviews again, until the score is good or the rounds
  run out. The report (score, rounds, applied fixes) is shown in the UI.
- **Overlay cards drawn locally: text, icons and lines, not AI images**. The presentation
  style no longer generates pictures with an image model: the overlay elements designed in
  the wizard (title, bullet points, icon concepts) are rendered as transparent PNG cards
  with Pillow — heading, accent line, bullets with vector glyphs (check, arrow, star,
  alert, dot) and icon chips — composited over the clips while the video keeps playing.
  Four card styles (Scuro, Chiaro, Blu notte, Carta); without a designed plan the
  narration line becomes the card title. Fast, free and pixel-precise.
- **Video wizard: the Clip studio becomes a guided flow**. Step 1 turns the prompt into the
  full narration (the AI also advises whether subtitles are worth it) and sets the target
  duration to the reading time. Step 2 picks the narrator voice. Step 3 describes what each
  scene should show and prefills the stock-search queries. Step 4 chooses the presentation
  style: with the overlay layer on, the AI designs the text/icon elements that will float
  over the video. Step 5 searches the sources (YouTube, Wikimedia Commons, Pixabay) from the
  scene queries, previews the candidates inline and lets you swap any that do not fit
  (alternative queries on demand). Step 6 downloads and cuts the audio-free clips into the
  catalog. Step 7 selects the best clips, writes the script and applies the designed
  overlays. Step 8 picks the transition between clips from a list. Step 9 renders the fast
  silent preview and then the final video.
- **Overlays: infographics on top of the video, not instead of it**: a new script syntax
  `![](picture.png){overlay}` composites a transparent image over the shot's clip — it slides in,
  drifts gently and can carry a real alpha channel (PNG with transparency). The *Add
  illustrations* step in the Clip studio now generates overlays instead of standalone shots, so
  the video keeps playing underneath. A **none** caption style in the Video, AI Video and Clip
  studio tabs renders the video without captions.
- **Video duration matches the narration reading time by default**: a new estimate of the
  reading time (words at a natural ~150 wpm pace plus the renderer's pauses) drives both the
  Clip studio and the AI Video tab. In the Clip studio a checkbox (on by default) makes the
  model write the narrations to a word budget that reads in about the target duration, and the
  status reports the measured reading time next to the target — move the duration slider and
  re-select (or edit the script) to stretch or shorten the video. The AI scene planner gets the
  same per-scene word budget from the requested duration.
- **Google Colab notebook** (`colab/ai_voiceover_studio.ipynb`): the full web studio (all tabs,
  including AI Video and Clip studio) runs on Colab without any local setup — the keys
  (`OPENROUTER_API_KEY`, `PIXABAY_KEY`) come from the Colab secrets, a check cell tests both
  sources before launching, and the UI is served on a public `*.gradio.live` link with a
  one-click results zip. The notebook is tuned for a YouTube-free workflow: Pixabay (plus the
  keyless Wikimedia Commons) for footage and OpenRouter image models for illustrations, so it
  installs only the `webui` and `edge` extras (no yt-dlp, no deno, no cookies).
- **Quick preview and presentation-style illustrations in the Clip studio**: before the full
  render, a *Quick preview* button produces a fast, silent, low-resolution draft (dummy voice,
  half resolution, separate `preview.mp4`) so the flow can be checked HeyGen-style in seconds.
  A new *Add illustrations* step inserts AI-generated images between the narration shots of the
  script (every 1–3 shots, editable script afterwards): the image is requested from an OpenRouter
  image model (`modalities: ["image"]`, selectable model and aspect ratio, six artistic styles
  such as *Infografica illustrata*), and the renderer's Ken Burns motion turns each one into a
  moving infographic. A failed illustration is reported and skipped, never fatal.
- **Live progress in the Clip studio**: the build button now streams the work log into the status
  box as it happens, with elapsed seconds per step, instead of showing everything only at the
  end; clips are classified **in parallel** (3 at a time) so the batch finishes noticeably faster.
- **Target duration drives the Clip studio**: a new field asks for the final video duration at
  the start; from it the studio estimates how many shots, clips and sources are needed, caps the
  clips extracted per source, and **stops the batch as soon as enough clips are cut** — no more
  videos are downloaded than the target requires. The final selection picks as many shots as the
  duration implies.
- **Stock-footage sources with real descriptions in the Clip studio**: the search now runs on
  selectable sources — YouTube, **Wikimedia Commons** (keyless, richly described videos,
  downloaded directly over HTTPS: no cookies, no bot checks, no rate limits) and **Pixabay**
  (professionally tagged cinematic footage, free API key shown at the top of
  pixabay.com/api/docs/ when logged in, or `VOICEOVER_PIXABAY_KEY`). Candidates preview inline
  (embedded player for YouTube, direct video tag for the stock sources) and flow into the same
  select → download → classify → catalog pipeline.
- **Editable search queries in the Clip studio**: the model's suggested YouTube queries are now
  shown in an editable form (one per line) before searching, so the search no longer returns the
  same generic results; queries written by hand work without any API key.
- **Clip catalog and automatic final cut**: every extracted clip is classified in detail by the
  model (description, tags, mood, setting, camera move, people check) and stored in a JSON
  database (`clip_library/catalog.json`) together with the audio-free clip files; downloads are
  spaced by a configurable pause to stay under YouTube's rate limits; from the video prompt and
  the catalog the model then selects the best 3–8 shots, writes the narration for each, and the
  tab renders the final video with a narrator voice chosen in the tab itself.
- **Clip studio tab**: write the prompt of the video and get a reusable B-roll library. The
  OpenRouter model (or *best value (auto)*, which ranks the catalogue by price per token) turns
  the prompt into several varied YouTube searches — at least five distinct sources, people-focused
  titles filtered out — the candidates preview inline without downloading, you select the videos,
  and yt-dlp downloads them; their subtitles feed the model to pick self-contained highlight
  segments, ffmpeg cuts **audio-free** clips and extracts still frames, and the *Video* tab lets
  you tick exactly which clips and frames to reuse. New optional extra `clip` (`yt-dlp[default]`,
  which bundles the yt-dlp-ejs challenge solver that YouTube now requires; a JavaScript runtime
  such as deno or Node must also be on the machine). One failing URL no longer aborts the
  batch; YouTube bot checks are reported with cookie instructions (`VOICEOVER_YTDLP_COOKIES` for a
  cookies.txt file, `VOICEOVER_YTDLP_COOKIES_FROM_BROWSER` for the browser profile, or the
  cookies field in the tab).
- **Transition controls in the Video tab**: transition style (mix, fade, slide, zoom, cut) and
  duration are now selectable in the UI, on top of the existing CLI flags.
- **AI Video tab**: a one-line prompt becomes a finished video. An OpenRouter model plans the
  scenes (narration + search keywords), keyless sources (Wikimedia Commons, Openverse) provide the
  visuals, Pollinations generates images when nothing matches, and an optional vision check on the
  same OpenRouter key rejects assets that do not match the scene. The editable scene plan turns
  into a Markdown script rendered by the existing video engine.
- **Web studio**: `voiceover studio` serves a local Gradio web app (optional extra
  `pip install "ai-voiceover-studio[webui]"`) to write or load a script, pick engine, language and
  speed, generate and listen to the voiceover with its SRT and segment table, voice single lines,
  browse the engine's voices (click a row for an instant sample preview) and render the MP4 when
  ffmpeg is installed, with optional B-roll images or clips uploaded in the browser.
- Use-case guides with runnable commands in `docs/use-cases/` (faceless YouTube, Shorts / Reels /
  TikTok, explainer and recap narration, multilingual dubbing, podcast and audiobook snippets).
- Spanish example script `examples/script.es.md`.
- `llms-full.txt` (all docs in one file, built by `scripts/build_llms_full.py`), `CITATION.cff`,
  Code of Conduct, security policy, issue and pull request templates, social preview image.

### Changed
- `--lang` now also chooses the automatic voices for a whole script (e.g. `--lang es` gives Spanish
  voices for every speaker); before, it was only a hint for reference audio.
- README (all languages): definition, who it is for, use cases and a neutral comparison table;
  FAQ reorganised around common questions; `llms.txt` follows the llmstxt.org format.

## [0.3.0] - 2026-11-07

### Added
- **Word-by-word animated captions** (`--style tiktok`, the new default for vertical video): 1-4 big
  words at a time, thick outline, the spoken word pops in and turns yellow, keywords stay green. Also
  `bold` (huge words revealed as spoken) and an upgraded `clean` (calm two-line captions with a soft
  highlight, default for landscape). Timing comes from the edge engine's word boundaries
  (`meta["words"]`), or a reading-speed estimate for other engines. Safe areas for 9:16 and 16:9.
- **B-roll in the script**: `![](image-or-clip)` above a paragraph shows it while the paragraph is
  spoken; several images share the paragraph's time; video clips are trimmed or looped.
  `**bold**` words become caption keywords.
- **Background music with ducking**: `--music ambient|pulse` (generated by ffmpeg from this project's
  own code at render time, no licence involved) or `--music FILE`; levelled, faded, and lowered under
  the voice with a sidechain compressor (`--music-volume`, `--no-duck`).
- **Animated hook card** from the script's `# heading` (`--hook`, `--hook-seconds`, `--no-hook`).
- **Kinetic typography** for parts without a picture: animated gradient + the key phrase building up
  in large type.
- Transitions mix (`--transition-style mix|fade|slide|zoom|cut`), a light cinematic grade
  (`--grade cinematic|none`: contrast, vignette, grain), smoother Ken Burns (four moves on a
  supersampled canvas), `--vertical` shortcut.
- New demo: `examples/demo.en.md` (16:9) and `examples/demo.zh.md` (9:16) with generated B-roll in
  `examples/broll/`; new `docs/assets/demo.gif`, `demo-short-zh.gif`, `demo.mp4`, `demo-short-zh.mp4`.

### Changed
- `--title` is now the hook card (alias `--hook`) and is shown whenever the script has a heading.
- `--speed`, `--tag` and other CLI voice options now also apply to automatically picked voices.
- Fonts given as a file are matched by their real family name, so single-weight files
  (e.g. `Montserrat-ExtraBold.ttf`) work with libass.
- The video is encoded in a temporary folder and moved into place (fixes `+faststart` on some
  network / FUSE file systems).
- Removed the old clip-art example slides (`examples/slides`, `examples/make_slides.py`).

## [0.2.0] - 2026-11-07

### Added
- **Free `edge` engine** (Microsoft Edge neural voices via `edge-tts`, extra `[edge]`): no account or
  key; it is the default engine when `MIRAGEA_API_KEY` is not set. Sentence boundaries reported by the
  engine are used for subtitle timing; network errors are retried; clear message for unusable
  proxy URLs (`VOICEOVER_EDGE_PROXY`).
- **`openai` engine** (`OPENAI_API_KEY`, standard library HTTP, `tags` become a speaking-style instruction).
- **Automatic voices per speaker**: without a voices file every speaker gets its own voice, chosen from the
  script's language (edge, openai, dummy) or from the actors saved in the Miragea account.
- **New video renderer** built on a single ffmpeg graph: Ken Burns zoom/pan with easing, cross-fades
  (`--transition`), progress bar, title card from the script's first heading, gradient background when no
  images are given, `--fit contain` with a blurred backdrop.
- **Caption styles** (`--style clean|box|bold|minimal`), `--speaker-labels`, `--font`; caption size and
  line length adapt to landscape and vertical video; CJK-aware.
- **`voiceover doctor`** (`--online`, `--json`): checks Python, ffmpeg filters (libass, xfade), engines,
  API keys (never shown), default engine and CJK fonts, with a fix for each problem.
- `voiceover voices --filter TEXT`; `voiceover say` without `--voice` picks a voice from the text's language.
- Real demo media in `docs/assets/` (GIF, MP4, MP3, SRT, vertical Chinese Short) and redrawn example
  slides generated by `examples/make_slides.py`.

### Changed
- Default engine is resolved as: `--provider` / `VOICEOVER_PROVIDER`, else `miragea` when
  `MIRAGEA_API_KEY` is set, else `edge`.
- `voiceover video` burns styled captions by default (`--subtitles burn`) and still writes the `.srt`;
  `--images` is optional.
- Video no longer depends on moviepy; the `[video]` extra is kept (empty) for compatibility.
- Subtitle cues never overlap.
- Miragea requests send a browser-compatible User-Agent that still names the tool.

## [0.1.0] - 2026-11-07

### Added
- `voiceover say`: text to speech for a single line, with actor ids or a reference-audio URL (voice cloning).
- `voiceover script`: multi-speaker Markdown/TXT scripts (`[SPEAKER]:` tags, `[pause N]`, per-line
  `tags`/`speed`/`model`/`lang`), speaker → voice mapping via `voices.json` / `voices.yaml`,
  concatenation with configurable gaps, `manifest.json`, and a per-segment cache.
- SRT subtitles from segment timing (default) or provider speech recognition (`--subtitles recognize`).
- `voiceover video`: faceless slideshow video (moviepy) with sidecar or burned-in subtitles,
  landscape or vertical sizes.
- `voiceover voices` (account voice list, pagination) and `voiceover task` (resume/inspect a task).
- Provider interface (`VoiceProvider`) with entry-point discovery; built-in `miragea` provider
  (async tasks, polling, deterministic idempotency keys, retry on retryable errors, clear
  401/403/409/413/429 messages) and offline `dummy` provider.
- Agent skill `skills/ai-voiceover/SKILL.md`, `--json` output and stable exit codes.
- Offline test-suite with mocked HTTP.
